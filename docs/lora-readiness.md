# DevMentor 피드백과 LoRA 준비 상태

## 1. 결론

피드백 수집과 학습 적격성 판정은 구현했습니다. 실제 LoRA 학습은 실행하지 않았습니다.

현재 저장소에는 사용자가 학습 활용에 동의한 검수 데이터 seed나 import가 없습니다. 따라서 최소 수백 건 조건을 충족하지 않으며, 지금 학습하면 품질과 개인정보 양쪽에서 근거가 없습니다.

## 2. 수집 데이터

사용자가 AI 답변에 피드백을 저장하면 다음 값을 서버가 snapshot합니다.

- 사용자 질문과 생성 답변
- 도움됨 또는 수정 필요
- 사용자가 작성한 수정 답안
- 학습 활용 동의와 동의 시각
- 모델 provider, tag, digest·양자화 식별자
- 프롬프트 버전
- 응답 시간과 구조화 fallback 유형
- 모델에 제공한 RAG 문서 ID
- 피드백 갱신·철회 시각

클라이언트가 모델명이나 출처를 임의로 제출하지 않고, AI 답변 생성 시 서버가 `ChatMessage`에 저장한 값을 사용합니다.

## 3. 동의와 삭제

- 학습 동의 기본값은 `false`입니다.
- `NOT_HELPFUL` 답변을 학습에 사용하려면 수정 답안이 필요합니다.
- 같은 답변의 피드백은 한 행에서 갱신합니다.
- 삭제 요청 시 `trainingConsent=false`, `deletedAt`을 기록합니다.
- 철회된 데이터는 적격성 집계와 향후 학습 후보에서 제외해야 합니다.

물리 파기 보존 기간은 인증·개인정보 운영 정책과 함께 별도로 확정해야 합니다.

## 4. 학습 적격성 게이트

| 조건 | 최소값 | 현재 판정 |
| --- | ---: | --- |
| 학습 동의 피드백 | 300건 | 저장소 기준 데이터 없음 |
| 검수된 수정 답안 | 200건 | 저장소 기준 데이터 없음 |
| 분리 평가셋 | 36건 고정 평가셋 | 준비 |
| 인증된 export 경계 | 관리자 전용 | 미구현 |
| 기반 모델 운영 품질 | Task 12·13 게이트 | 미통과 |

확인 명령:

```powershell
.\scripts\check-lora-eligibility.ps1
```

exit code `2`는 실패가 아니라 학습 금지 게이트가 정상 작동한 상태입니다.

## 5. 적격성 통과 후 순서

1. 동의를 철회한 행과 개인정보·비밀정보를 제외합니다.
2. 사용자 또는 대화 단위로 train/validation/test 누수를 차단합니다.
3. 기반 모델 digest, 양자화, 학습 설정, 데이터 manifest를 고정합니다.
4. LoRA 어댑터를 별도 이름으로 생성하고 기본 모델을 덮어쓰지 않습니다.
5. Task 9 고정 평가셋과 분리 test set으로 정확성·한국어·Schema·안전성·속도를 비교합니다.
6. 개선이 없거나 안전 지표가 악화되면 배포하지 않습니다.

현재 단계에서는 위 절차를 실행할 데이터와 운영 권한이 없으므로 학습 코드 추가도 보류합니다. 이는 미구현을 숨기는 것이 아니라 잘못된 학습을 막는 명시적 중단 조건입니다.
