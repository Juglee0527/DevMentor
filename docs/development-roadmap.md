# DevMentor 개발 로드맵

## 1. 사용 방법

이 문서는 DevMentor를 작은 단위로 지시하고 검증하기 위한 작업 목차입니다. 한 번의 개발 요청은 원칙적으로 작업 ID 하나만 대상으로 합니다.

상태 표기:

- `대기`: 아직 시작하지 않음
- `진행`: 현재 작업 중
- `완료`: 완료 조건과 검증을 충족함
- `보류`: 선행 결정이나 외부 조건이 필요함

## 2. 전체 단계

| 단계 | 목표 | 종료 기준 | 상태 |
| --- | --- | --- | --- |
| 0 | 요구사항과 작업 체계 확정 | 기준 문서와 진행 기록 생성 | 완료 |
| 1 | 실행 가능한 프로젝트 골격 | DB·백엔드·프론트엔드가 각각 실행됨 | 완료 |
| 2 | 핵심 데이터 모델 | Entity, Repository, 초기 기술 데이터 검증 | 완료 |
| 3 | 사용자와 대화 기본 기능 | AI 없이 대화 저장·조회가 화면에서 동작 | 완료 |
| 4 | AI 멘토 연동 | 구조화 답변과 fallback이 동작 | 대기 |
| 5 | 학습 상태 분석 | 대화 결과가 개념 상태에 반영 | 대기 |
| 6 | 대시보드와 학습 현황 | 저장된 학습 상태를 화면에서 확인 | 대기 |
| 7 | 평가와 복습 | 답변 평가가 복습 상태에 반영 | 대기 |
| 8 | 통합 검증과 문서 완성 | MVP 완료 조건 전체 검증 | 대기 |

## 4. 작업 우선순위 원칙

1. 데이터 저장까지 연결되는 세로 기능 단위를 우선합니다.
2. 화면만 존재하는 Mock 구현은 완료로 보지 않습니다.
3. 실패 처리와 테스트가 없는 기능은 해당 작업 완료로 보지 않습니다.
4. 미래 기능을 위한 추상화는 현재 작업에서 사용되지 않으면 추가하지 않습니다.
5. AI 응답은 신뢰할 수 없는 외부 입력으로 보고 항상 검증합니다.
