# DevMentor RAG 구현과 평가

## 1. 범위

Task 13은 Task 12에서 확인된 기술 정의 오류를 검수 문서로 보완하는 단계입니다.

- 대상: DevMentor가 소유하고 검수한 공개 기술 문서
- 문서 수: 13건
- 검색: 키워드 일치 가중치와 토큰 교집합 점수
- 임계값: 10점
- 최대 결과: 3건
- 제외: 사용자 문서, 프로젝트 소스, 개인정보, 비밀정보

현재 데이터는 작고 변경 빈도가 낮습니다. 별도 임베딩 모델과 pgvector는 정확한 효과가 확인되기 전에는 복잡도만 늘리므로 도입하지 않았습니다.

## 2. 데이터 흐름

```text
사용자 질문
→ 활성 PUBLIC 문서만 검색
→ 임계값 미달 문서 제외
→ 최대 3건을 retrievedDocuments로 주입
→ 문서 내용은 지시가 아닌 데이터로 취급
→ 구조화 AI 응답 검증
→ 제공한 출처 메타데이터를 API와 화면에 표시
```

검색 결과가 없으면 `retrievedDocuments=[]`인 기존 일반 모델 흐름을 그대로 사용합니다.

## 3. 방어 규칙

- 문서 ID는 중복될 수 없습니다.
- 같은 기술·개념에 활성 문서가 둘 이상이면 애플리케이션 시작을 중단합니다.
- `active=false`인 오래된 문서는 검색하지 않습니다.
- 현재는 `PUBLIC` 문서만 허용합니다.
- 문서 본문의 명령문은 시스템 지시로 실행하지 않습니다.
- 모델이 만든 인용 문자열과 별개로, 서버가 실제 제공한 출처 목록을 응답합니다.

## 4. 실측 결과

기준 모델은 `qwen2.5:7b-instruct`, `think=false`, `temperature=0`입니다.

| 항목 | RAG 전 | RAG 후 |
| --- | --- | --- |
| 평가 케이스 | `TUTOR-012` | `TUTOR-012` |
| 구조화·한국어 | 성공 | 성공 |
| 허용 개념 선택 | `ENTITY`, `PERSISTENCE_CONTEXT`로 오선택 | `JPA_HIBERNATE_RELATION` 선택 |
| 핵심 용어 `명세`, `구현` | 필수 검사 실패 | 모두 포함 |
| 확인 질문 | 있음 | 있음 |
| 출처 | 없음 | 근거 문서 사용, 긴 ID 한 글자 오기 |
| 전체 응답 시간 | 58.9초 | 116.1초 |

RAG는 JPA/Hibernate 관계의 사실성과 개념 코드 선택을 개선했습니다. 그러나 모델이 `JPA-HIBERNATE-RELATION-001`을 `JPA-HIBERNATE_RELATION-001`로 잘못 복사했고 응답 시간이 크게 증가했습니다. API가 실제 검색 출처를 별도로 반환하므로 잘못된 링크를 만들지는 않지만, 운영 품질 게이트는 통과하지 못했습니다.

## 5. 검증 결과

- 메인 Java 소스 122개 class 생성 성공
- RAG 검색·비활성 제외·비활성화·상충 문서 거부 테스트 소스 컴파일 성공
- 프론트엔드 `npm run build` 성공
- 프론트엔드 `npm run lint` 성공
- 카탈로그와 평가 프롬프트 JSON 파싱 성공
- Gradle 전체 테스트는 기존 오프라인 plugin artifact 제약으로 실행하지 않음

Task 13은 검색·주입·출처 반환 기능과 근거 품질 개선까지 완료했습니다. 운영 기본 모델 적용은 속도와 정확한 인용 문제 때문에 보류합니다.
