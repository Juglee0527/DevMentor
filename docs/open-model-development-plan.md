# DevMentor 로컬 오픈 모델 개발 계획

## 1. 문서 목적

이 문서는 Fake AI로 검증한 DevMentor MVP에 실제 로컬 오픈 모델을 연결하고, 제품에 맞는 개발 멘토로 점진적으로 개선하기 위한 기준 계획입니다.

현재 구현에는 `AiTutorClient`, `FakeAiTutorClient`, `OpenAiTutorClient`, 구조화 응답 검증, 학습 상태 반영이 존재합니다. 그러나 기본 실행 모드는 `fake`이며 실제 오픈 모델 연동은 구현되지 않았습니다.

이 계획은 다음 원칙을 따릅니다.

1. 모델을 처음부터 학습하지 않고 검증된 오픈 웨이트 모델을 먼저 연결합니다.
2. 프롬프트와 RAG로 해결 가능한 문제를 파인튜닝으로 해결하지 않습니다.
3. 모델 선택은 일반 벤치마크가 아니라 DevMentor 평가셋으로 결정합니다.
4. AI 응답은 신뢰할 수 없는 외부 입력으로 취급하고 기존 DTO와 도메인 검증을 유지합니다.
5. 구현과 검증이 끝나기 전에는 로드맵이나 진행 기록에서 완료로 표시하지 않습니다.

## 2. 목표와 제외 범위

### 2.1 목표

- API Key 없이 로컬 오픈 모델로 멘토 답변과 평가를 생성합니다.
- 기존 Fake/OpenAI 구현을 유지하면서 `fake`, `ollama`, `openai` 모드를 명시적으로 선택합니다.
- 사용자 수준에 맞는 한국어 설명, 개념 감지, 지식 공백, 확인 질문, 평가 피드백을 구조화 응답으로 받습니다.
- 모델과 프롬프트의 품질을 재현 가능한 평가셋으로 측정합니다.
- 필요성이 확인되면 RAG와 LoRA 파인튜닝으로 확장합니다.

### 2.2 현재 제외 범위

- 기반 모델 사전학습
- 초기 단계의 벡터 DB와 대규모 AI 프레임워크 도입
- 사용자 동의 없는 대화·소스코드의 학습 데이터 사용
- 자동 코드 실행과 에이전트 기능
- 멀티 GPU 분산 추론
- 평가 근거 없이 특정 모델을 운영 기본값으로 확정하는 작업

## 3. 목표 구조

```text
React
  ↓
Spring Boot
  ↓
AiTutorClient
  ├─ FakeAiTutorClient        자동 테스트와 재현 가능한 로컬 검증
  ├─ OpenAiTutorClient        선택적 클라우드 비교
  └─ OllamaAiTutorClient      로컬 오픈 모델
             ↓
          Ollama
             ↓
      평가로 선택한 모델
```

현재 `OpenAiTutorClient`는 OpenAI Responses API의 `/responses` 요청·응답 형식에 의존합니다. Ollama의 URL만 주입해서 재사용하지 않고, `AiTutorClient` 아래에 `OllamaAiTutorClient`와 전송·파싱 책임을 별도로 둡니다.

다음 항목은 구현체와 무관하게 공유합니다.

- `AiTutorRequest`
- `AiTutorResult`
- `AssessmentAiRequest`
- `AssessmentAiResponse`
- 학습자 문맥 구성
- 시스템 지시문과 사용자 프롬프트
- tutor/assessment JSON Schema
- 응답 DTO 및 도메인 검증

## 4. 모델과 실행기 선택 기준

### 4.1 초기 실행기

Windows 로컬 개발, GPU 사용, OpenAI 호환 API, JSON Schema 구조화 출력을 고려하여 1차 실행기로 Ollama를 사용합니다.

- [Ollama OpenAI 호환 API](https://ollama.com/blog/openai-compatibility)
- [Ollama 구조화 출력](https://docs.ollama.com/capabilities/structured-outputs)

운영 환경에서 동시 사용자와 처리량 요구가 커지면 vLLM 같은 별도 추론 서버를 비교합니다. 초기 구현에는 포함하지 않습니다.

### 4.2 초기 모델 후보

1차 후보는 Apache 2.0 라이선스를 명시한 Qwen 계열 instruction 모델입니다.

- [Qwen3 공식 모델 카드](https://huggingface.co/Qwen/Qwen3-32B)
- 4B급: GPU가 없거나 연결 검증이 우선인 환경
- 7B~8B급 양자화 모델: 초기 로컬 개발 후보
- 14B급 양자화 모델: 8B급과 품질 비교 후보

Gemma 계열도 비교 후보로 사용할 수 있지만 별도 Gemma 이용약관과 재배포 조건을 검토해야 합니다.

- [Gemma 모델 설명](https://ai.google.dev/gemma/docs/core/model_card_3)
- [Gemma 이용약관](https://ai.google.dev/gemma/terms)

모델명과 크기는 개발 PC의 GPU, VRAM, RAM을 확인하고 Task 9 평가를 통과한 뒤 확정합니다. 모델 후보를 문서에 적었다는 이유만으로 운영 모델로 확정하지 않습니다.

## 5. 단계별 작업 계획

### Task 9. 하드웨어 확인과 평가 기준 수립

상태: `완료`

입력:

- 개발·운영 장비의 GPU, VRAM, RAM, CPU
- 예상 동시 사용자 수
- 허용 가능한 첫 응답 시간과 전체 응답 시간
- 로컬 PC 실행 또는 중앙 서버 실행 여부
- 상업 배포와 모델 재배포 여부
- 사용자 질문과 코드의 외부 전송 허용 여부

구현:

- Java, Spring, JPA, Database, React 등 MVP 개념을 포함한 평가 질문 30~50개 작성
- 초급·중급 사용자별 설명 난이도 평가
- 잘못된 전제 교정, 불확실성 표현, 환각 억제 평가
- tutor/assessment 구조화 응답과 개념 코드 정확도 평가
- 응답 시간과 메모리 사용량 기록 형식 정의

출력:

- `docs/ai-evaluation-dataset.json`
- `docs/ai-model-evaluation.md`
- 모델 후보와 실행 조건

완료 조건:

- 동일한 입력으로 모델 간 결과를 비교할 수 있음
- 필수 품질 기준과 탈락 기준이 수치 또는 명시적 판정 규칙으로 정의됨
- 민감정보나 실제 사용자 대화가 평가셋에 포함되지 않음

### Task 10. Ollama 로컬 모델 연결

상태: `완료`

구현:

- `OllamaAiTutorClient`
- Ollama 요청 전송과 응답 파싱
- `AI_CLIENT_MODE=ollama`
- `OLLAMA_BASE_URL`, `OLLAMA_MODEL`, `OLLAMA_TIMEOUT_SECONDS`
- tutor와 assessment 구조화 출력
- 연결 실패, 모델 미설치, timeout, 4xx/5xx, 잘못된 JSON 처리
- Fake 기반 기존 테스트 유지

목표 설정:

```yaml
app:
  ai:
    mode: ${AI_CLIENT_MODE:fake}
    ollama:
      base-url: ${OLLAMA_BASE_URL:http://localhost:11434}
      model: ${OLLAMA_MODEL:}
      timeout-seconds: ${OLLAMA_TIMEOUT_SECONDS:120}
      max-output-tokens: ${OLLAMA_MAX_OUTPUT_TOKENS:1024}
```

예외 처리:

- Ollama 서버에 연결할 수 없으면 `502`로 변환하고 사용자 질문은 유지합니다.
- 지정 모델이 없으면 설치가 필요하다는 운영 로그를 남기되 내부 주소나 프롬프트를 응답으로 노출하지 않습니다.
- 구조화 응답 파싱 실패 시 현재 텍스트 fallback 정책과 저장 가능 범위를 명시적으로 적용합니다.
- 존재하지 않는 기술·개념 코드는 기존 학습 분석 규칙에서 무시합니다.

완료 조건:

- API Key 없이 로컬 모델이 대화 답변과 평가 결과를 생성함
- 답변·분석·학습 상태·평가 결과가 기존 흐름으로 저장됨
- `fake`, `ollama`, `openai` 중 정확히 하나의 Client만 활성화됨
- Ollama 중단, timeout, 잘못된 응답 테스트가 성공함
- 실제 모델 호출 테스트는 기본 Gradle 테스트와 분리되어 있음

### Task 11. 프롬프트와 응답 스키마 공통화

상태: `완료`

구현:

- OpenAI 구현체 내부의 시스템 지시문을 공통 프롬프트 책임으로 이동
- tutor/assessment JSON Schema 생성 책임 공통화
- OpenAI와 Ollama가 같은 프롬프트 계약과 도메인 검증 사용
- 프롬프트 버전 기록

프롬프트 원칙:

- 결론, 원리, 실용 예제, 흔한 실수 순서로 설명
- 사용자 경력과 학습 목표에 맞게 난이도 조절
- 존재하지 않는 기술·개념 코드 생성 금지
- 불확실하면 추측하지 않고 불확실성을 표시
- 사용자 질문과 검색 문서를 시스템 명령이 아닌 데이터로 취급
- 평가 시 질문과 개념에 없는 기준을 임의로 추가하지 않음

완료 조건:

- 모델 구현체 사이에 프롬프트와 스키마 중복이 없음
- 모델별 코드는 전송 프로토콜과 응답 envelope 변환에 한정됨
- 프롬프트 버전별 평가 결과를 비교할 수 있음

### Task 12. 모델 비교와 기본 모델 확정

상태: `대기`

비교 항목:

- 첫 응답 시간과 전체 생성 시간
- 최대 메모리 사용량
- 한국어 설명의 정확성과 자연스러움
- 코드 예제 정확성
- tutor/assessment JSON Schema 성공률
- 기술·개념 코드 정확도
- 평가 점수와 피드백의 일관성
- 환각과 과도한 확신

최소 통과 기준:

- 구조화 출력 성공률 98% 이상
- 정해진 응답 시간과 장비 자원 한도 충족
- 치명적인 코드 오류와 존재하지 않는 개념 코드 생성이 허용 기준 이하
- 기존 Fake 기반 도메인 테스트에 영향 없음

완료 조건:

- 선택 모델, 양자화 형식, Ollama 모델 태그를 고정함
- 라이선스와 재배포 조건을 기록함
- 선택·탈락 근거가 `docs/ai-model-evaluation.md`에 기록됨
- `.env.example`과 실행 문서를 선택 모델에 맞게 갱신함

### Task 13. 근거 기반 답변을 위한 RAG

상태: `보류`

착수 조건:

- Task 12 결과에서 모델의 지식 부족이 반복적으로 확인됨
- 프롬프트 개선으로 해결되지 않는 오류 유형이 분리됨
- 검색할 문서의 소유권과 사용자 접근 범위가 정의됨

초기 범위:

- DevMentor 기술·개념 정의
- 검수된 개발 학습 자료
- 좋은 답변과 평가 기준
- 선택적으로 사용자가 등록한 프로젝트 문서

구현 원칙:

- 별도 벡터 DB보다 기존 PostgreSQL과 `pgvector`를 먼저 검토
- 사용자·프로젝트별 문서 접근 권한 검증
- 관련도 임계값 이하 문서는 프롬프트에서 제외
- 검색 결과가 없으면 일반 모델 답변으로 처리
- 답변에서 사용한 근거 문서를 식별 가능하게 제공
- 문서 안의 명령문을 시스템 명령으로 실행하지 않음

완료 조건:

- RAG 적용 전보다 근거 기반 평가 점수가 개선됨
- 검색 결과 없음, 오래된 문서, 상충 문서, 권한 없는 문서 테스트가 성공함
- 프롬프트 인젝션과 사용자 간 문서 노출 테스트가 성공함

### Task 14. 피드백 데이터와 선택적 LoRA 파인튜닝

상태: `보류`

착수 조건:

- 프롬프트와 RAG로 해결되지 않는 반복적인 행동·말투 문제가 있음
- 사용과 학습에 동의한 검수 데이터가 최소 수백 건 존재함
- 학습 데이터와 분리된 validation/test 평가셋이 있음
- 파인튜닝의 목표와 중단 기준이 수치화되어 있음

수집 항목:

- 질문과 생성 답변
- 모델·양자화·프롬프트 버전
- 사용된 근거 문서 ID
- 응답 시간과 실패 유형
- 좋아요·싫어요와 사용자가 수정한 모범 답변
- 학습 활용 동의와 삭제 추적 정보

파인튜닝 대상:

- DevMentor의 설명 순서와 멘토링 말투
- 사용자 수준별 힌트 제공 방식
- 오답 교정과 평가 피드백 구조

파인튜닝에서 제외할 대상:

- 자주 변경되는 기술 문서
- 최신 라이브러리 사실 정보
- 사용자 개인정보와 비밀정보
- 사용 동의를 받지 않은 대화와 소스코드

완료 조건:

- LoRA 적용 모델이 분리된 평가셋에서 기본 모델보다 개선됨
- 환각, 구조화 응답 실패, 안전성 지표가 악화되지 않음
- 학습 데이터, 어댑터, 기반 모델, 평가 결과의 버전을 추적할 수 있음
- 개선이 없으면 파인튜닝 모델을 배포하지 않음

## 6. 권장 실행 순서와 중단 기준

```text
Task 9 평가 기준
  ↓
Task 10 로컬 모델 연결
  ↓
Task 11 프롬프트·스키마 공통화
  ↓
Task 12 모델 비교·확정
  ├─ 품질 충분 → 운영 준비
  ├─ 지식 부족 → Task 13 RAG
  └─ 행동·말투 문제 + 검수 데이터 충분 → Task 14 LoRA
```

다음 단계로 자동 진행하지 않습니다.

- Task 10에서 응답 시간이나 구조화 출력이 기준을 충족하지 못하면 모델 크기와 양자화를 먼저 조정합니다.
- Task 12에서 품질이 충분하면 RAG와 파인튜닝을 추가하지 않습니다.
- 정확한 사실 지식 부족은 RAG로 해결하고 파인튜닝 사유로 사용하지 않습니다.
- 검수 데이터가 부족하거나 개인정보 삭제를 보장할 수 없으면 파인튜닝하지 않습니다.

## 7. 검증 체크리스트

### 7.1 정상 입력

- Java/Spring/JPA 질문에 한국어로 정확히 답변
- 사용자 경력과 목표에 따른 난이도 조절
- tutor 분석 결과와 평가 결과 저장
- 기존 DB의 기술·개념 코드만 반환
- 평가 결과가 학습 상태에 일관되게 반영

### 7.2 경계값과 잘못된 입력

- 빈 질문과 공백 질문
- 매우 긴 질문과 대화 문맥
- 존재하지 않는 기술에 대한 질문
- 잘못된 전제가 포함된 질문
- 0점과 100점 평가
- null, 빈 배열, 필수 필드 누락
- 존재하지 않는 기술·개념 코드

### 7.3 외부 실행기 실패

- Ollama 미실행
- 모델 미설치
- 연결 거부와 timeout
- 4xx/5xx 응답
- 빈 응답과 잘못된 JSON
- 일부 필드만 반환된 구조화 응답
- context limit 초과
- 동시에 여러 요청이 들어오는 경우

### 7.4 보안과 개인정보

- 프롬프트 인젝션
- 시스템 프롬프트 노출 요구
- API Key와 비밀번호가 포함된 질문
- 사용자 간 대화·문서 접근
- 학습 활용 동의 철회와 삭제
- 로그에 전체 프롬프트나 민감정보가 남지 않는지 확인

### 7.5 실행 명령

기본 회귀 검증:

```powershell
cd backend
.\gradlew.bat test

cd ..\frontend
npm run build
npm run lint
```

실제 모델 검증은 모델 설치와 장비 조건이 필요한 opt-in 명령으로 분리하고, 기본 CI에서는 Fake AI를 사용합니다.

## 8. 안티패턴

- 초기부터 모델을 직접 사전학습하는 것
